# Спецификация: локализация нативных клиентов

- Дата: 2026-08-02
- Статус: accepted
- Связанный ADR: `docs/adr/0008-native-client-localization.md`

## Намерение

Пользователь должен видеть Andivum на русском или английском языке сразу после
первого запуска, без обязательной ручной настройки. При необходимости он может
явно выбрать язык для конкретного устройства.

## Наблюдаемое поведение

1. Given системный язык начинается с `ru`, When приложение запускается впервые,
   Then интерфейс отображается на русском.
2. Given системный язык начинается с `en`, When приложение запускается впервые,
   Then интерфейс отображается на английском.
3. Given системный язык неизвестен, недоступен или не поддерживается, When
   приложение запускается впервые, Then интерфейс отображается на русском.
4. Given пользователь выбирает `System`, `English` или `Русский`, When выбор
   сохраняется, Then он применяется к этому устройству и переживает перезапуск.
5. Given пользователь возвращается к `System`, When язык системы изменён,
   Then приложение выбирает язык по системной локали при следующем применении
   конфигурации.
6. Given UI отображает количество элементов, When число меняется, Then целая
   локализованная фраза выбирается через platform plural rules, а не собирается
   конкатенацией в UI-коде.

## Границы

### Входит

- `en-US` и `ru-RU` с полным переводом пользовательского интерфейса;
- автоматический выбор по языковой семье системы;
- русский fallback для неизвестной или неподдержанной системной локали;
- ручной выбор `System / English / Русский`;
- локальное хранение выбора языка на устройстве;
- `.resw` для Windows и `strings.xml/plurals` для Android;
- CLI-проверка паритета ключей, placeholders и plural-форм после создания
  клиентских проектов.

### Не входит

- общий runtime JSON или общая библиотека локализации;
- синхронизация языка через аккаунт;
- третья локаль;
- локализация backend UI-сообщений;
- runtime-ресурсы до появления соответствующих native client проектов.

## Ошибки и восстановление

- Отсутствующий перевод не должен приводить к пустому контролу: платформа
  использует английскую базовую ресурсную локаль, а CI блокирует неполный набор
  ключей.
- Если смена языка не может обновить уже открытое окно, приложение сообщает,
  что настройка вступит в силу после перезапуска.

## Данные и безопасность

- Настройка языка не содержит секретов и хранится в локальном хранилище
  настроек платформы.
- Backend API использует стабильные error codes; локализация выполняется
  клиентом.

## Платформенные различия

- Windows: MRT Core, `Resources.resw`, `x:Uid`, `ResourceLoader` и
  `ApplicationLanguages.PrimaryLanguageOverride`.
- Android: `strings.xml`, `plurals`, `stringResource`,
  `pluralStringResource` и AndroidX per-app locales.

## Критерии приёмки

- [ ] На обеих платформах есть полный `en-US` и `ru-RU` набор ресурсов.
- [ ] Автовыбор различает `ru-*`, `en-*` и fallback `ru-RU`.
- [ ] Ручной выбор переживает перезапуск приложения.
- [ ] Возврат к `System` снова использует язык ОС.
- [ ] Plural forms проверены на русском и английском.
- [ ] Backend не возвращает локализованные UI-фразы.
- [ ] `pnpm i18n:check` проверяет ключи, placeholders, plural-формы и
  соответствие `config/product.json`.

## Проверки

- [ ] Unit: resolver системной локали и policy fallback.
- [ ] Windows UI: переключение и перезапуск окна.
- [ ] Android UI: per-app locales и Compose recomposition.
- [ ] Integration: стабильные API error codes.
- [ ] Localization/theme/accessibility.
