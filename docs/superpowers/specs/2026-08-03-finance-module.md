# Спецификация: модуль финансов

- Дата: 2026-08-03
- Статус: accepted
- Владелец: AI под продуктовым руководством владельца Andivum

## Намерение

Дать пользователю отдельное место для учёта личных денег: быстро внести доход
или расход вручную, разобрать чек/письмо/документ в редактируемый черновик и
получить понятные сводки без риска незаметно записать ошибку распознавания.

## Наблюдаемое поведение

1. Given пользователь авторизован, When он открывает «Финансы», Then модуль
   загружает счета, системные и пользовательские категории и последние
   операции, а чужие строки недоступны через RLS.
2. Given пользователь создаёт расход, When он добавляет одну или несколько
   позиций и выбирает категорию для каждой, Then сервер сохраняет одну
   транзакцию и все позиции атомарно; сумма позиций обязана совпасть с общей
   суммой.
3. Given пользователь выбирает фото, PDF, EML, CSV или текстовый документ,
   When приложение запускает импорт, Then файл проходит проверку размера и
   MIME/расширения, извлекается текст там, где это возможно, а для изображения
   или PDF при включённом Gemini строится JSON-черновик.
4. Given AI/OCR вернул неполный или противоречивый результат, When пользователь
   видит черновик, Then он может изменить название, дату, тип, сумму, каждую
   позицию и категорию; автоматическое сохранение без подтверждения запрещено.
5. Given пользователь дважды импортирует тот же файл/банковскую строку, When
   второй импорт доходит до проверки, Then приложение показывает найденный
   дубль и не создаёт вторую операцию молча.
6. Given пользователь задаёт Gemini API key, When ключ сохраняется, Then он
   остаётся только в защищённом хранилище ОС, не синхронизируется и не
   попадает в логи; AI-вызов выполняется по HTTPS.

## Модель данных

- `finance_accounts`: счёт пользователя, тип счёта, валюта и баланс в minor
  units.
- `finance_categories`: дерево категорий с `parent_id`, типом `expense` или
  `income`, системным набором и пользовательскими категориями.
- `finance_transactions`: заголовок операции, `income`/`expense`/`transfer`,
  дата, счёт, валюта, итог, источник и отпечаток импорта.
- `finance_transaction_items`: строки транзакции с названием, количеством,
  ценой, итогом и собственной категорией.
- `finance_attachments`: метаданные чека/письма без хранения API key; файлы
  лежат в приватном Storage bucket с путём, начинающимся с user id.

Суммы передаются как `bigint` minor units; дробные вычисления денег в
клиентах запрещены. Количество может быть дробным, но итог строки всегда
передаётся уже округлённым целым числом minor units.

## Категории первого набора

Стартовый каталог ориентирован на личный бюджет и включает жильё, коммунальные
услуги, продукты, кафе, транспорт, автомобиль, здоровье, одежду, образование,
связь, подписки, развлечения, путешествия, детей, животных, подарки, налоги,
комиссии и благотворительность. Доходы намеренно короче: зарплата, премия,
фриланс, бизнес, проценты, дивиденды, возврат, подарок и прочее.

Каждая запись имеет стабильный slug, локализованные имена и родителя. Системные
категории нельзя удалить; пользователь может создать свою подкатегорию или
скрыть системную.

## Импорт

Поддерживаемые входы первой версии: JPEG/PNG/HEIC/WEBP, PDF, EML, TXT, CSV,
OFX/QFX и вложения, переданные через системный file picker. Лимит одного файла
— 20 MiB, PDF — не более 100 страниц после проверки. Расширение не считается
достаточным доказательством типа: MIME и сигнатура проверяются до обработки.

Порядок обработки:

1. локальная проверка размера, расширения, MIME и SHA-256;
2. безопасное извлечение UTF-8/Windows-1251 текста из EML/TXT/CSV и базовых
   банковских форматов;
3. локальный OCR, если платформа его предоставляет;
4. по явному включению пользователя — Gemini с ограниченной схемой JSON;
5. нормализация дат, разделителей, валют и чисел;
6. черновик с полями confidence/provenance и предупреждениями;
7. подтверждение пользователем и атомарная запись.

AI не имеет права выбирать произвольную категорию: модель получает список
разрешённых category slug, а неизвестное значение превращается в
`uncategorized`. JSON проходит строгую валидацию и повторную проверку суммы.

## Ошибки и восстановление

- нет сети: ручной ввод остаётся доступен, импортированный файл остаётся
  локальным черновиком;
- не поддержан файл: понятное сообщение и возможность выбрать другой способ;
- OCR/AI не уверен: сохраняется текст и предупреждение, но не транзакция;
- API key неверен/исчерпан лимит: ключ не показывается в ошибке, предлагается
  выключить AI или повторить позже;
- конфликт/дубликат: операция не создаётся автоматически;
- частичная запись: серверная RPC-транзакция откатывает заголовок и строки
  вместе.

## Платформенные различия

- Windows: WinUI 3 NavigationView, системный FileOpenPicker, PasswordVault для
  Gemini key; быстрый OCR может быть заменён облачным разбором при отсутствии
  локального движка.
- Android: Material 3 NavigationBar, `ACTION_OPEN_DOCUMENT`, Android Keystore
  для Gemini key, ML Kit Text Recognition для локального OCR изображений.

## Безопасность

- используется только publishable key Supabase и пользовательский Bearer JWT;
- таблицы и Storage имеют RLS-политики по `auth.uid()`;
- Gemini key не отправляется в Supabase, не синхронизируется и не попадает в
  аналитические события;
- оригиналы документов хранятся приватно и удаляются пользователем отдельно;
- AI получает только выбранный документ и минимальный prompt; приложение
  показывает, что документ может уйти внешнему провайдеру.

## Критерии приёмки

- [ ] отдельная активная вкладка «Финансы» на Windows и Android;
- [ ] ручное создание income/expense с одной и несколькими строками;
- [ ] дерево категорий и большой системный набор;
- [ ] деньги хранятся без floating point;
- [ ] RLS и атомарная RPC-запись;
- [ ] импорт фото/PDF/EML/CSV/OFX/QFX в редактируемый черновик;
- [ ] локальный OCR/текстовый fallback и Gemini structured JSON;
- [ ] защищённая настройка Gemini key;
- [ ] duplicate detection и regression tests;
- [ ] русская и английская локализация;
- [ ] `pnpm check`, `git diff --check`, реальные сборки доступных платформ.

## Основания решения

Модель строк транзакции следует практике split transactions из GnuCash; импорт
с предварительным сопоставлением и защитой от дублей — практике Actual Budget и
Firefly III; Gemini используется только как структурированный помощник, потому
что его официальные API поддерживают PDF и JSON Schema. Для Android локальный
OCR опирается на ML Kit Text Recognition v2.
