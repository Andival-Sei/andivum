# Email/password authentication vertical slice

- Статус: в работе
- Дата: 2026-08-02
- Решение: `docs/adr/0012-email-password-authentication.md`

## Цель простыми словами

Кнопка входа в Windows или Android открывает системный браузер. В браузере
пользователь может либо войти по email и паролю, либо зарегистрироваться. После
этого приложение получает обычный безопасный пропуск и проверяет его у сервера.
Пароль в приложение не попадает.

Passkey остаётся дополнительной возможностью: его можно подключить уже после
входа в настройках аккаунта.

## Входит

- форма входа email + пароль на `/connect/authorize`;
- форма регистрации email + пароль + повтор пароля;
- серверная валидация и безопасное хэширование пароля через ASP.NET Identity;
- lockout после повторных неудачных попыток;
- продолжение исходного OIDC authorization request после успешного входа или
  регистрации;
- общий сценарий для Windows и Android через существующий PKCE-клиент;
- passkey sign-in для уже подключённых passkeys;
- authenticated settings page, где можно начать подключение passkey;
- API-тесты на страницу, регистрацию, вход, CSRF и отсутствие требования
  passkey для email/password аккаунта;
- обновление понятных текстов native login UI.

## Не входит

- подтверждение email письмом;
- восстановление пароля и recovery codes;
- logout-all-devices;
- прямой API вход с передачей пароля из native client;
- полная ручная проверка двух устройств одним пользователем.

## Критерии готовности

1. Анонимный OIDC-запрос показывает формы входа и регистрации email/password.
2. Валидная регистрация создаёт Identity account и возвращает authorization code
   на точный native callback.
3. Уже созданный пользователь может войти тем же способом и получить code.
4. После email/password входа наличие passkey не требуется для выдачи code.
5. Неверный пароль не выдаёт code и не раскрывает, существует ли email.
6. Пароль не появляется в URL, callback, UI native-клиента или логах.
7. Подключение passkey доступно только authenticated account settings.
