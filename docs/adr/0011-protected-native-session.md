# ADR-0011: Проверка и обновление native-сессии

- Статус: принято
- Дата: 2026-08-02
- Область: Identity, Windows, Android

## Контекст

Наличие токена в локальном хранилище ещё не доказывает, что сервер считает
сессию действительной. Кроме того, access token короткоживущий и должен
обновляться без повторного входа пользователя.

## Решение

После получения или восстановления токенов Windows и Android вызывают
защищённый `GET /api/v1/session`. Backend извлекает `sub` из проверенного
OpenIddict principal и возвращает стабильный `userId`.

Native clients запрашивают `offline_access`. Windows явно обновляет токены при
истечении и один раз повторяет запрос после `401`; Android передаёт управление
обновлением AppAuth через `performActionWithFreshTokens`. Новая пара токенов
сохраняется только в Credential Locker или Android Keystore-backed storage.

Dashboard показывается только после успешной проверки endpoint. UI отображает
человеческий статус проверки, но не access token, refresh token или `userId`.

## Последствия

- Windows и Android используют один серверный критерий авторизованной сессии.
- Один и тот же `userId` позволяет подтвердить, что устройства работают с одной
  аккаунтной записью.
- Logout, account recovery и logout-all-devices остаются отдельными срезами.
- Реальный Windows Hello smoke требует ручного действия владельца и не входит
  в автоматизированный тест агента.

## Защита

- Backend test проверяет `401` для анонимного запроса и стабильный `userId`.
- Windows test проверяет refresh, ротацию refresh token и повтор защищённого
  вызова.
- Android instrumentation test проверяет разбор ответа с тем же контрактом.
