# ADR 0010: Passwordless account bootstrap без обязательной почты

- Статус: принято
- Дата: 2026-08-02

## Контекст

Первый authentication slice должен позволить владельцу создать аккаунт только
с помощью passkey. Продукт пока не определил обязательный email, username или
провайдера восстановления. Добавление такого поля сейчас стало бы
неподтверждённым продуктовым решением и расширило бы поверхность хранения
персональных данных.

## Решение

При первом запуске регистрации сервер создаёт Identity-пользователя с
неприводимым к человеку техническим `UserName` и временно устанавливает
browser-сессию только для завершения passkey attestation. OAuth authorization
code выдаётся только аккаунту, у которого сохранён хотя бы один passkey.

Имя passkey является отображаемой меткой credential, а не идентификатором
аккаунта. Повторная попытка pending-регистрации переиспользует pending account,
а не создаёт дополнительный аккаунт.

## Security review

- Pending browser cookie не даёт bearer-доступа к API.
- `/connect/authorize` повторно проверяет наличие passkey перед выдачей code.
- Mutating endpoints требуют anti-forgery token.
- Credential JSON, токены и authorization codes не логируются.
- Recovery, email verification и account management остаются отдельными
  решениями и не считаются реализованными.

## Последствия

Первый путь регистрации остаётся коротким и privacy-friendly, но до появления
recovery пользователь несёт ответственность за доступ к своим passkeys. Email,
имя аккаунта и восстановление добавляются отдельным ADR после появления
требований продукта.
